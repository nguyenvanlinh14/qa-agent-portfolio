# CLAUDE.md

Instructions for Claude Code (and any other AI agent) working in this repository.
Humans: this file is also the contract that the test framework follows.

## Project overview

`qa-agent-portfolio` is a QA Automation portfolio. It contains:

- A **system under test (SUT)**: `server/app.mjs` serves the built site from `dist/` and a small REST API
  (`/api/health`, `/api/auth/login`, `/api/todos`, `/api/test/reset`) on port 4173.
- A **TaskFlow demo app** in `site/demo/` (login + todos, localStorage based). Its behaviour must not change.
- A **Playwright + TypeScript framework** (page objects, fixtures, data builders, API client, visual tests).
- An **AI agent layer**: the agents in `.claude/agents/`, slash commands in `.claude/commands/`, Playwright MCP
  in `.mcp.json`, AI triage in CI (`scripts/ai-triage.mjs`) and the `@claude` workflow.
- A **static site** (`site/` + `docs/lessons/*.md`, Vietnamese lessons) built into `dist/` by `scripts/build-site.mjs`
  and deployed to GitHub Pages by CI.

Demo credentials: `qa@demo.dev` / `Passw0rd!`.

## Commands

| Command | What it does |
|---|---|
| `npm run build` | Build the site into `dist/` (runs automatically before `npm test`) |
| `npm run serve` | Start the SUT on http://localhost:4173 |
| `npm test` | Build, then run all Playwright projects |
| `npm run test:ui` / `test:api` / `test:visual` | Run one project |
| `npx playwright test <file> --project=ui` | Run a single spec |
| `npx playwright test --grep @smoke` | Run only smoke tests |
| `npm run test:update-snapshots` | Local snapshot update (do NOT commit the result, see rules) |
| `npm run report` | Open the HTML report |
| `npm run typecheck` | `tsc --noEmit` |
| `npm run ai:triage` | Summarise failures from `reports/results.json` (uses the Anthropic API if a key is set) |
| `npm run k6:smoke` / `k6:load` | k6 against the API |

Never run `npx playwright install`: the browser is already installed locally, and CI uses the Playwright Docker image.

## Framework rules

1. **Locator priority:** `getByRole` > `getByLabel` > `getByTestId` > CSS. Use `getByText`/`getByPlaceholder`
   only when none of those fit. Never use XPath or positional selectors (`nth-child`) unless there is no alternative,
   and then comment why.
2. **No hard sleeps.** Never use `waitForTimeout`, `setTimeout`-based waits or `page.waitForLoadState('networkidle')`
   as a synchronisation crutch. Rely on auto-waiting and web-first assertions.
3. **Web-first assertions only:** `await expect(locator).toBeVisible()`, `toHaveText`, `toHaveCount`, `toHaveURL`.
   Do not assert on `await locator.isVisible()` / `textContent()` results with plain `expect(...)`.
4. **One behaviour per test.** A test has one reason to fail. Small and independent; no test depends on another test.
5. **Test data comes from `tests/data/`** (factories/builders such as `TodoBuilder`). No magic strings or numbers
   inline in specs, except values the assertion is explicitly about.
6. **Every test is tagged `@smoke` or `@regression`** (in the title or the `tag` option). Smoke = fast critical path.
7. **Page objects expose locators and actions. Assertions live in specs**, never inside page objects.
   Page objects extend `BasePage` and are provided through fixtures in `tests/fixtures/index.ts`.
8. **Specs import `test` and `expect` from `tests/fixtures`**, not from `@playwright/test`.
9. **Never weaken an assertion to make a test pass.** Do not loosen matchers, drop assertions, widen timeouts to hide
   a race, or add `.skip`/`.fixme` without a human decision. A red test is information.
10. **Never call `/api/test/reset` from tests that run in parallel.** It clears ALL todos and tokens for everyone.
    Isolate with unique data per test (builders generate unique titles) and clean up what you create.
    Reset is only acceptable in a serial describe block that is the sole user of the API at that time.
11. **Visual baselines are only updated through the `update-snapshots` workflow** (Linux, Playwright Docker image).
    Never commit locally generated screenshots and never run `--update-snapshots` to make CI green.
12. **Types:** strict TypeScript, no `any`; `npm run typecheck` must pass.
13. **No secrets, no personal email/phone** in code, fixtures, plans or docs.

## Review checklist (use before approving any test change)

- [ ] Title describes a single behaviour; tagged `@smoke` or `@regression`.
- [ ] Locators follow the priority order; no CSS where a role or label exists.
- [ ] No `waitForTimeout`, no sleeps, no `networkidle` waits.
- [ ] Only web-first assertions; assertions are in the spec, not in the page object.
- [ ] Data from `tests/data/`; unique per test; created data is cleaned up.
- [ ] No `/api/test/reset` in parallel code paths.
- [ ] No weakened or removed assertions compared with the plan or previous version.
- [ ] Test passes alone and in the full run (`--repeat-each=3` for anything that looks racy).
- [ ] `npm run typecheck` is green.

## How agents work here

The workflow is **plan, generate, review, heal, triage**. A human approves between stages.

1. **Plan**: `test-planner` explores the running app with the Playwright MCP browser and writes a Markdown plan
   to `specs/plans/<feature>.md` (scenarios, steps, expected results). Human reviews the plan.
2. **Generate**: `test-generator` turns the approved plan into page-object-based specs following the rules above,
   runs them, and reports. Human reviews the diff with the checklist.
3. **Review**: a human (or `@claude` on the PR) checks the diff against the checklist.
4. **Heal**: when a test fails because the UI changed, `test-healer` re-inspects the DOM via MCP and fixes
   **locators and navigation only**. It may not change assertions or expected values, and must explain every change.
   If an expectation looks wrong, it stops and reports instead.
5. **Triage**: `flaky-triager` (read-only) classifies failures from `reports/results.json` and traces as
   product bug / test bug / flaky / environment. CI also runs `scripts/ai-triage.mjs` and writes the summary
   to the job summary.

Slash commands: `/gen-test <feature>`, `/heal <spec>`, `/triage`.

Agent guardrails: agents propose, humans approve. Agents never commit to `main`, never push snapshots, never
edit `server/app.mjs` or `site/demo/` to make a test pass, and never touch CI secrets. When in doubt, stop and ask.
